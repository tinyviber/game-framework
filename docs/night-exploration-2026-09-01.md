# 夜间玩法探索报告 · 2026-09-01

> 目标：为"持久探索型解谜世界"方向做大范围机制搜索，留下 3 个可玩原型供人类裁决。
> 本报告不做最终选择；所有"证据"均来自可玩 spike，而非 LLM 自评。

---

## 0. 起点基线

- 种子驱动的 40×40 正交 RPG 世界（草地/森林/河流/高地/岩石屏障），WASD 移动，E 检查，I 库存 overlay。
- 世界状态深冻结、操作原子化（`applyScopedOperation`），遍历规则由 cells + 有向 edges（normal/stairs/ramp/height-barrier）决定。
- 旧 2.5D/等距渲染器保留但未触碰。

---

## 1. 发散：26 个机制方向

模板：玩家动作 / 世界反馈 / 可学习规则 / 谜题潜力 / 组合性 / 隐含计算结构（内部信息）/ 失败模式。

### A. 容器与顺序语义

**1. 轻重祭坛（Sifting Shrine）**
- 动作：捡拾不同重量的种子，走近石祭坛把怀里的东西全投进去，再按 E 让它"吐"出一个。
- 反馈：祭坛总是先吐出当前最轻的那个，吐出的东西落在祭坛前的石台上。
- 规则：容器有自己的内在顺序——最轻的永远先出来。
- 谜题：你需要"最后才出来的那个重种子"去压门闩，就得先处理掉挡在前面的轻杂物；携带上限迫使来回跑。
- 组合：与重量机关（#25）、水流推动（#24）、合成（#12）组合。
- 隐含结构：优先队列（堆）。玩家永远不会听到这个词。
- 失败模式：退化成"换皮背包 UI"；若吐出顺序不可预测则显得武断。

**2. 回声井（LIFO 井）**
- 动作：把物件投入深井；摇辘轳时只能取回最后投进去的那个。
- 反馈：井台只露出最上层的物件。
- 规则：后进的先出。
- 谜题：井底沉着钥匙，但你之前投入的杂物压在它上面——必须先清场；或故意"埋"一个物件留给未来的自己。
- 组合：与祭坛（#1）并置形成"两种容器两种顺序"的对照谜题。
- 隐含结构：栈。
- 失败模式：与 #1 太像，单独立项价值低；教程感强。

**3. 配重门（Exact-Weight Plates）**
- 动作：把石块/物品压上门前石盘，多了弹开、少了不动。
- 反馈：石盘下沉深度可视化，门只在恰好匹配时开。
- 规则：门认"总重"不认"物件"。
- 谜题：手边没有正好的石头 → 需要拆分/合并物品，或用自己的体重+物品凑数。
- 组合：与祭坛的轻重语义、合成拆分组合。
- 隐含结构：子集和（subset-sum）/背包。
- 失败模式：数值调参感强、试错繁琐；容易变成算术作业。

### B. 自我状态与时间

**4. 回声锚点（Echo Anchor）** ★ 原型 B
- 动作：按 Q 在脚下留一个半透明"回声"；再按 Q 瞬间回到回声处（回声消散）。
- 反馈：回声以幽灵形态站在原地；回程时世界"闪回"。
- 规则：你永远可以回到自己锚定的位置，但锚只有一个。
- 谜题：过一次性断桥 → 开机关 → 回声返回；直观计划（走过去再走回来）被塌桥打断，回声是修复手段。
- 组合：塌桥、单向落差、限时门、影子门（#7）。
- 隐含结构：检查点/回溯（continuation）；单槽撤销。
- 失败模式：若处处可用则消解所有空间谜题张力；需要"什么不能用回声解决"的反向设计。

**5. 录音幽灵（Record/Replay Ghost）**
- 动作：按 R 开始"演示"20 步，幽灵按你的录像循环行动。
- 反馈：半透明幽灵重复你的路径，可以替你压石盘、挡机关。
- 规则：过去的你可以成为现在的你的工具。
- 谜题：需要两人同时踩两个石盘 → 录一段踩盘路线再放行。
- 组合：配重门、定时门。
- 隐含结构：确定性自动机回放/协程。
- 失败模式：实现与可读性成本高；玩家难以预判幽灵时序，挫败感强。今晚不做。

**6. 镜厅分身（Mirror Twin）**
- 动作：进入镜厅后，镜像以对称方式复制你的每一步。
- 反馈：两个角色同步移动，撞墙的一方原地踏步。
- 规则：你控制的是"一对"。
- 谜题：让镜像走到你去不了的开关处；利用撞墙踏步制造相对位移。
- 组合：塌桥、石盘。
- 隐含结构：并行模拟/对称变换群。
- 失败模式：需要专门房间几何，和生成世界不兼容；规则反直觉，容易读不懂。

**7. 昼夜祭坛（Day/Night Switch）**
- 动作：转动祭坛切换昼夜。
- 反馈：某些门/植物/水路只在特定时段可用，整个世界状态切换。
- 规则：世界是双稳态的。
- 谜题：白天走不通的路夜里出现；需要在两种状态间接力搬运物件。
- 组合：冻泉（#9）、藤蔓（#10）。
- 隐含结构：双状态机/布尔域切换。
- 失败模式：粒度太粗，一切谜题都变成"换边再试"；需要差异化内容量大。

### C. 地形状态变换

**8. 冻泉法器（Frost Vessel）** ★ 原型 C
- 动作：按 F 开启凝霜气场，身边的水面结成可踩的冰；冰在数步后融化。
- 反馈：水格变白成冰；融化时裂开；站在融化的冰上会落水被冲回岸边。
- 规则：你能短暂地"改写"水的可走性，但冰有寿命。
- 谜题：河心的珠子在两步之外——规划冻结顺序与步数预算；直观计划（直接下水捡）被打断。
- 组合：水流（#24）、配重门、回声锚点（落水前锚定）。
- 隐含结构：状态空间重写/可达性闭包的时变版本。
- 失败模式：融化计时不直观则显得惩罚随机；几何依赖种子，需要挑选合适世界。

**9. 重力冰面（Slide）**
- 动作：踏上冰面后沿方向滑行直到撞上障碍。
- 反馈：角色不受控地滑过整片冰。
- 规则：冰面剥夺中途停止权。
- 谜题：经典冰面迷宫——用岩石/树木做"刹车"规划停点；推动石块改变刹车布局。
- 组合：推箱（#11）、冻泉（自己造冰）。
- 隐含结构：确定性状态机/函数复合。
- 失败模式：与现有格子移动语义冲突（需要"滑行移动"新动词）；纯冰面谜题已被无数游戏做过，差异化要靠组合。

**10. 藤蔓时钟（Timed Growth）**
- 动作：种下藤蔓种子，走过 N 步后它长成可攀的藤墙。
- 反馈：藤蔓随你的步数分阶段生长。
- 规则：世界是"按你的步数计时"的。
- 谜题：需要在藤蔓长成时恰好回到它旁边；步数预算成为资源。
- 组合：高地（藤蔓=梯子）、昼夜。
- 隐含结构：计数器/延迟求值。
- 失败模式：反馈慢，玩家难以建立因果；等待感强。

**11. 推石（Sokoban Blocks）**
- 动作：推动圆石，石停下水口、压住石盘、垫脚登高。
- 反馈：石头直线滚动一格（或滑到底）。
- 规则：石头是世界的可重写几何。
- 谜题：经典推箱变体 + 石头推入水中成踏脚石。
- 组合：冰面、水流、配重门、高地。
- 隐含结构：状态空间搜索（推箱是 PSPACE-complete，但不必告诉玩家）。
- 失败模式：容易做成又一个推箱克隆；需要与地形语义（水/高差）深度咬合才有新意。

**12. 水位闸门（Sluice Valves）**
- 动作：扳动水闸，整片水域水位涨落。
- 反馈：低处的路被淹/露出，高处的船搁浅/浮起。
- 规则：水位是全局状态，一改全改。
- 谜题：先放水拿到干涸渠底的钥匙，再蓄水浮起木筏渡湖。
- 组合：冻泉（冰只在有水处）、回声锚点。
- 隐含结构：全局不变量切换/分层可达性。
- 失败模式：需要大面积水域几何，生成世界目前只有窄河带；全局切换的因果可视化难。

**13. 元素转化炉（Transmutation）**
- 动作：用火炬/水壶/种子对环境施放元素：火烧林、水灭火、冻水、藤蔓爬墙。
- 反馈：地形类型被改写（森林→焦土→可通行）。
- 规则：元素间有稳定的转化环。
- 谜题：转化有代价/次数，需要规划转化链。
- 组合：几乎一切。
- 隐含结构：项重写系统（term rewriting）。
- 失败模式：系统太大，一晚做不出可信切片；容易变成"哪里不会点哪里"的万能钥匙。

### D. 空间网络与门

**14. 风向祭坛（Wind Vanes）**
- 动作：转动风向标改变风口方向；走进风口被吹过沟壑。
- 反馈：可见气流带；角色被推送数格。
- 规则：风是单向传送带，方向可配置。
- 谜题：配置多个风口接力到达目的地；风也是打断（想直走却被吹偏）。
- 组合：冰面、回声锚点。
- 隐含结构：有向图边的重配置。
- 失败模式：风道可视化成本高；与格子移动的"一步一格"手感冲突。

**15. 镜面水潭（Portal Ponds）**
- 动作：走进一潭，从配对的另一潭浮出。
- 反馈：成对水潭有同色光晕；进入即传送。
- 规则：潭是固定的点对。
- 谜题：传送网络的路径规划；把物件投入潭中传送。
- 组合：祭坛（传送容器吐出物）、推石。
- 隐含结构：图同构/置换。
- 失败模式：一次性 gimmick 风险高；"开放内部、封闭外部"里它更像是捷径工具而非谜题本体。

**16. 共振水晶（Linked Crystals）**
- 动作：敲响一块水晶，所有同色水晶共鸣，联动门开/关。
- 反馈：同色水晶同步闪烁，远处门状态翻转。
- 规则：同色=同一线路。
- 谜题：需要 A 开 B 关的组合 → 找水晶配色方案。
- 组合：昼夜、水位。
- 隐含结构：等价类/并查集。
- 失败模式：规则不透明（远处变化看不见因果）；易退化成"挨个敲一遍"。

**17. 路标网络（Waypoint Signs）**
- 动作：激活路标后可从任一路标传送回已激活的路标。
- 反馈：路标点亮，地图网络逐步展开。
- 规则：你亲手铺设快速旅行图。
- 谜题：更像探索 QoL 而非谜题；激活顺序可做成资源规划。
- 组合：几乎所有。
- 隐含结构：图的增量构建。
- 失败模式：不是谜题机制，是便利设施；今晚不优先。

**18. 缝合捷径（Stitched Shortcuts）**
- 动作：消耗"线团"把两个曾到访的位置缝成一对传送门。
- 反馈：地面出现发光的缝线门。
- 规则：玩家自己创造图边，但线团有限。
- 谜题：把有限的"新边"加在哪里使整个路线连通/最短。
- 组合：回声锚点、塌桥。
- 隐含结构：图编辑/最短路重计算。
- 失败模式：经济平衡难；自由度过高导致谜题解不收敛。

### E. 信息与观察

**19. 记忆灯笼（Reveal Lantern）**
- 动作：提灯行走，灯光半径内隐藏的桥/路显形，离开后数秒隐去。
- 反馈：隐藏路径若隐若现，需要记忆路线。
- 规则：世界有"只有被观察时才存在"的部分。
- 谜题：记住隐形桥的全貌，在黑暗中按记忆走过去。
- 组合：塌桥、冰面。
- 隐含结构：隐藏状态/认知逻辑。
- 失败模式：记忆负担过重会劝退；与"状态必须可见"的可读性原则张力大。

**20. 影子门（Shadow Gates）**
- 动作：举火把靠近，门在光照下显形/在阴影中才可穿过。
- 反馈：光照半径动态改变门的实体性。
- 规则：光与影分别是一组门的钥匙。
- 谜题：同一条走廊白天（亮）和持影（灭）是两条路。
- 组合：昼夜、灯笼。
- 隐含结构：布尔域上的双图。
- 失败模式：光照渲染成本高；规则与昼夜（#7）重叠。

**21. 绘图迷雾（Cartography Fog）**
- 动作：走过的区域被绘入地图；可买到"测绘风筝"俯瞰局部。
- 反馈：小地图从全黑到逐步显影。
- 规则：知识即地图，地图即能力。
- 谜题：更像元 progression；可卖地图给 NPC 换工具。
- 组合：路标网络。
- 隐含结构：增量信息获取/探索-利用。
- 失败模式：UI 重，机制本身不产生谜题；已有 debug minimap 占了部分心智。

### F. 代理与生态

**22. 蜂群引路（Pheromone Trail）**
- 动作：撒花粉画出轨迹，萤火虫沿轨迹飞行，替你触发远处机关。
- 反馈：光点沿线移动，碰到机关触发。
- 规则：你可以"编程"一个简单代理的路径。
- 谜题：画线绕过障碍让萤火虫按顺序撞三个铃铛。
- 组合：配重门、共振水晶。
- 隐含结构：路径规划委托/代理模拟。
- 失败模式：间接控制的挫败感；轨迹绘制 UI 重。

**23. 动物变身（Form Swap）**
- 动作：在图腾处换形：鱼渡水、鸟越高、鼠钻洞。
- 反馈：形态决定可走地形集合。
- 规则：每个形态是一张独立的可达性图。
- 谜题：在正确位置换形接力；形态间搬运限制。
- 组合：冻泉、高地。
- 隐含结构：多层图/态射。
- 失败模式：内容量大（每形态要配得上谜题）；与"少数原语组合"原则冲突——它更像内容框架而非原语。

**24. 逆流河（One-Way Currents）**
- 动作：踏入水中即被水流冲向下游，直到浅滩。
- 反馈：入水即强制位移，可见流向箭头。
- 规则：水是单向自动扶梯。
- 谜题：选择入水点=选择终点；用石块（#11）改道。
- 组合：推石、冻泉（冻住=停流）。
- 隐含结构：函数/流向图。
- 失败模式：需要可靠的水流几何，生成器目前不保证；被动位移手感需要打磨。

### G. 合成与工具

**25. 断桥修补（Bridge Kit Crafting）**
- 动作：在工作台把木板+绳索合成桥套件，拖到断口处架设。
- 反馈：断口变成可通行的新桥。
- 规则：工具是"可携带的地形"。
- 谜题：材料有限，桥架在哪里决定哪些区域开放。
- 组合：缝合捷径（同为"玩家造边"）、配重。
- 隐含结构：资源约束下的图补全。
- 失败模式：容易变成跑腿收集（fetch quest）；工作台 UI 已存在但只是展示，交互闭环工作量大。

**26. 工具改变动作集（Tool Verbs）**
- 动作：获得钩子后可"拉"，获得锤后可"砸"——工具直接给移动/交互增加新动词。
- 反馈：拿到工具后，世界里原本装饰性的物件突然可交互。
- 规则：动作集是装备的函数。
- 谜题：旧区域在新动词下重语境化（open inside, sealed outside 的直接实现）。
- 组合：一切。
- 隐含结构：能力 = 态射集合；类型class 式能力约束。
- 失败模式：这是元原则而非单一机制；今晚作为评估透镜使用，不单独立项。

| 家族 | 成员 | 共同内核 |
|---|---|---|
| 容器与顺序 | 1, 2, 3 | 世界物件有内在的存取语义，顺序即谜题 |
| 自我与时间 | 4, 5, 6, 7 | 玩家自身状态（位置/历史/形态）成为可操作资源 |
| 地形变换 | 8, 9, 10, 11, 12, 13 | 改写格子级可走性/几何，时变或永久 |

| 信息观察 | 19, 20, 21 | 隐藏状态与可见性规则 |
| 代理生态 | 22, 23, 24 | 借他者（生物/水流/形态）扩展可达性 |
| 合成工具 | 25, 26 | 把世界物件/动作集当作可构造物 |

## 3. 六强候选及理由

1. **轻重祭坛（#1）**——"具身抽象"原则的最小可证伪切片：一条顺序规则能否在无术语的情况下被玩家自发学会。
2. **回声锚点（#4）**——直接服务"开放内部、封闭外部"与"直观计划+打断"；把回溯从元操作降格为世界内动词。
3. **冻泉法器（#8）**——地形变换家族里因果最可见的：水→冰的改写即时可见，融化制造计划压力。
4. **重力冰面（#9）**——规则一句话说完，组合深度已被类型学验证；作为"移动语义变体"候选保留。
5. **记忆灯笼（#19）**——信息家族代表，与持久探索方向的"观察"维度互补。
6. **水位闸门（#12）**——全局状态切换代表，"旧区域重语境化"能力最强，但几何依赖最重。

**落选理由（要点）**：

## 5. 原型实现细节与验证

### 5.1 原型 A · 轻重祭坛（Sifting Shrine）

**机制层**（`src/experiments/sifting-shrine/mechanic.ts`）：
- 单一魔法容器（`urn`）位于世界骨架路径上的某一格，初始包含 3 颗 seed：feather / pebble / gold（重量 1 / 2 / 3）。
- 容器按"最轻优先"出货——取出必须按 feather → pebble → gold 的顺序（重量升序），违反顺序的取出请求被拒。
- 携带上限（`CARRY_LIMIT`）；取出第 N+1 件时被拒。
- 世界骨架路径的特定格上有两个 pedestal（轻 pedestal、重 pedestal），分别只接受 feather 与 gold。
- 石门 `gate` 不可走，直到两个 pedestal 都已"放置对应的 seed"。
- 玩家动词：`toss`（把携带的 seed 投回容器以重置取出序列）、`sift`（按规则取出下一颗）、`place-light` / `place-heavy`（放到对应 pedestal）、`drop`（丢弃携带物）。

**测试**（`src/experiments/sifting-shrine/mechanic.test.ts`，13 个全绿）：顺序取出被锁定、携带上限、门仅在两 pedestal 填好后开、toss 重置序列、错序被拒。

**接线**（`src/main.ts`，分支 `0c0685c`）：按 E 在容器或 pedestal 旁自动判定——站在容器上：携带非空则 toss（投回），否则 sift（按重量顺序取下一颗）；站在 pedestal 上：place-light / place-heavy（放下对应 seed）。WASD 移动，R 重置，N 新 seed。HUD：门的开关、携带 N / 上限、容器内剩余。

**复现步骤**：
1. `git checkout experiment/night-a-sifting-shrine`；
2. `npm install && npm run dev`；
3. 浏览器打开 `http://localhost:5173/?seed=2026`；
4. 走到容器前，按 E 取物（按 feather→pebble→gold 顺序）；满了按 E 自动 toss 回容器；
5. 走到两个 pedestal，按 E 放下对应 seed（feather→轻，gold→重）；
6. 观察：两 pedestal 都填好后石门打开，可走到 goal。

### 5.2 原型 B · 回声锚点（Echo Anchor）

**机制层**（`src/experiments/echo-anchor/mechanic.ts`）：
- 玩家动词 `placeEcho` / `recallEcho`：
  - 第一次按 Q 在玩家当前位置留下一个回声标记（蓝圈）；
  - 第二次按 Q 召回——玩家瞬移回回声位置，回声消失；
  - 同一时刻只能存在一个回声（先召回才能再放）。
- 在世界骨架路径上挑选一段作为"fragile bridge"（3 格的木板桥）：玩家走过后，身后格被加入 `collapsedKeys`，不可再走。
- 桥梁之后是 `lever`：站在上面按 E 拉下，`leverPulled = true`。
- 骨架路径上的另一格是 `gate`：不可走，直到 `leverPulled === true`。
- `goal` 在 `gate` 之后一格；走到 goal 即胜。
- `isStranded(layout, state, position)`：玩家在 bridge/lever 一侧且至少一块桥板已塌、且没有未使用的回声，则 stranded——这是失去返回路的明确信号。

**测试**（`src/experiments/echo-anchor/mechanic.test.ts`，15 个全绿）：bridge collapse、lever pull、门状态、回声放置/召回互斥、isStranded 检测、复位。

**接线**（`src/main.ts`）：WASD 移动，Q 放/召回，E 拉 lever，R 重置，N 新 seed。绘制桥板（完好的棕色木板 vs 塌陷的深坑）、扳杆（橙色杆身）、石门（铁栅栏 vs 打开的轮廓）、回声幽灵（浅蓝圆圈）。

**复现步骤**：
1. `git checkout experiment/night-b-echo-anchor`；
2. `npm run dev`；
3. 浏览器 `http://localhost:5173/?seed=2026`；
4. 不放回声直接过桥拉 lever → 桥在身后塌，玩家被困在 far 侧（stranded 状态）；
5. R 重置再来：先按 Q 在起点放回声 → 过桥 → 拉 lever → 开 gate → 召回回声回到起点；
6. N 换 seed 看不同骨架。

### 5.3 原型 C · 冻泉法器（Frost Vessel）

**位置**：正交世界 seed=2026 上的一片窄河——岸（橙色沙地）在 y=0 行，x=4–7 列是水。河宽 4 格，但河心珠（treasure）要求四面环水，故被自动选在 (5,1)，spawn 在 (3,0)。

**机制层**（`src/experiments/frost-vessel/mechanic.ts`）：
- `FROST_RADIUS = 2`（曼哈顿）：按 F 冻结身边 5×5 菱形内的所有 water 格。
- `FROST_LIFETIME = 4`：每个冰格有 4 步寿命。
- 移动冻结——每移动一步，所有冰格寿命 -1，归 0 融化回水。
- 站在融化冰上 → 落水：玩家被冲回最近的 walkable 格，整个 spell 碎裂（所有冰立即清除），`drownCount += 1`。
- 走到 treasure 格 → `treasureTaken = true`，HUD 提示"✦ 拿到河心珠"。
- 场景搜索：`findFrostTrial(world)` 在世界骨架边找岸→2–3 步水深处四面环水、且两步内有岸的 treasure；35/41 seed 可玩。

**测试**（`src/experiments/frost-vessel/mechanic.test.ts` + `seed-scan.test.ts`，共 11 个全绿）：
- castFrost 只冻水格、半径内、刷新寿命；
- tryMoveFrost：未冻水 blocked、冰可走、走到 treasure 标记；
- advanceFrost：寿命递减、寿命 1 时下一步融；
- drowning integration：玩家上冰、冰融、被冲回 walkable；
- seed-scan：41 seed 中至少有一个可玩场景（实为 35+）。

**接线**（`src/main.ts`，commit `8a8eeca` + polish `ebb453e`）：WASD 移动，F 凝霜，R 重置，N 新 seed（自动用 `findTrialSeed` 找最近可玩 seed）。绘制白色半透明冰覆盖层（alpha 0.95，fragile 时 alpha 0.85 + 蓝色裂纹）、金珠（diamond）、相机跟随。

**复现步骤**：
1. `git checkout experiment/night-c-frost-vessel`；
2. `npm run dev`；
3. 浏览器 `http://localhost:5173/?seed=2026`；
4. 按 F（岸边施放）→ 看到 3 格白色冰覆盖层（4,0 / 4,1 / 5,0）；
5. 按 D 走到 (4,0) → 按 F 刷新/扩冰 → 按 S 走到 (4,1) → 按 F → 按 D 走到 (5,1) 取珠；
6. 故意失败测试：按 F 走一步后站在冰上反复移动 5+ 步 → 冰融 → 落水 → HUD"掉进水里" → 全冰清空 → 重新冻结。

## 6. 三个原型对比

| 维度 | A · 轻重祭坛 | B · 回声锚点 | C · 冻泉法器 |
|---|---|---|---|
| 机制类型 | 离散序列 | 玩家状态 + 环境破坏 | 地形状态改写 |
| 直观计划 | "按顺序取" | "过桥拉 lever 开路" | "下水捡珠" |
| 计划如何被打断 | 携带上限阻挡连续取货 | 桥在身后塌 | 水不可走 |
| 学到的规则 | 顺序不可跳过 | 一次性桥 → 必须留回声 | 步数预算 + 接力施放 |
| 玩家动作数 | 取物（3 次） | Q×2 + E×1 + 移动 | F×3 + 移动×3 |
| 单次体验时长 | 30 秒 | 1–2 分钟 | 1–2 分钟 |
| 失败模式 | "袋子太满"提示太生硬 | stranded 没强提示易困惑 | 落水是正确信号 |
| 死亡/重置 | 无（重置即可） | 无 | 落水被冲回（软失败） |
| 与既有库存系统咬合 | 重（顺序是属性） | 弱（扳杆/桥无物品） | 弱（无物品，但施法是动词） |

## 7. 证据与不确定性

### 7.1 强证据（建议明日优先评估）

- **A**：13 个测试全绿，13 个含/不含顺序的状态断言、门开启闭、携带上限、reset 路径。机制确定性 100%，但**未在浏览器中完成手工冒烟**（当晚受任务时间约束未做）。
- **B**：15 个测试全绿，桥 collapse、lever、stranded、召回归声都已断言。机制确定性 100%，但**未在浏览器中完成手工冒烟**。
- **C**：11 个测试全绿，浏览器**已完成冒烟**：3 次施放 + 3 步接力成功取珠、HUD 反馈正确、冰覆盖层视觉清晰（commit `ebb453e` polish 后）。

### 7.2 需要人类裁决的开放问题

1. **是否要让"取货顺序"和"桥崩塌"机制真的成为玩家会反复试错的发现点？** A 的机制完全被测试覆盖，玩家不会真的"试错"；B 的桥塌是必然发现的；C 的步数预算是被构造的——三者的"探索感"强弱不一。
2. **落水的"软失败 vs 硬死亡"**：C 选择软失败（冲回岸边）以保留"再试一次"的张力。是否偏好硬死亡（死亡画面 + 完整重置）？
3. **施法动词（F）的可学性**：C 的 F 凝霜没有前置暗示，玩家第一次看到河可能不知"按 F"。是否需要在岸边加视觉提示（"河边的符文圈"）？
4. **珠子/石门/扳杆作为"目标"的视觉锚点**：三原型都有清晰目标物（金珠 / 远处石门 / 河心珠）。是否同意"目标物应该是 diegetic 的可见物件"作为默认？
5. **接力的步数预算（4 步寿命）是否太短/太长？** 当前冰格只有 4 步，玩家很容易踩错。如果改为 5–6 步，"学规则"更慢但"试错"更宽容。

## 9. 今晚未实现但值得明日考虑的组合（C1–C10 候选）

1. **A × B**：金罐中的金币是回声锚点的"能量"——只有拿过金罐才能放回声。顺序与状态挂钩。
2. **B × C**：回声锚点是"冰封"的——放回声时一同冻结脚下；召回时冰不消失，可作"冰桥"的稳定来源。
3. **A × C**：陶罐按重量出水，但水是冰——冻一只陶罐，碎裂后留下"重量属性的冰"。
4. **三合一**：石门后面是一个陶罐，陶罐顺序由桥的塌陷状态解锁（需要先落水解锁），河心珠是罐的"钥匙"。
5. **多谜题房间**：三个原型作为同一世界的三间独立房间，玩家按需选择进入。
6. **观测者谜题**：珠子其实是玩家自己放下的——回声锚点 + 落水冲回形成"时间回环"。
7. **节奏控制**：冰的寿命由玩家按 E 手动减 1（步数预算由玩家掌控而非强制），节奏感更主动。
8. **链式桥**：门不止一个；每开一道门解锁下一段桥；回声锚点需要在每次塌陷前"打包"。
9. **道具门**：陶罐里的东西不只是顺序——不同种类（金/银/铜）影响门能开的颜色。
10. **潮汐水位**：全局水位上升/下降，让"什么时候冻结"变成时间博弈。
